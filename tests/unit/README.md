# Документация по юнит-тестам для приложения Test-cases Generator

## Обзор

Этот набор юнит-тестов покрывает основную логику Flask-приложения `app.py`, которое генерирует тест-кейсы для веб-форм с использованием AI API MentorPiece. Все тесты используют mocking для избежания реальных запросов к внешнему API.

## Структура тестов

Тесты организованы в классы по функциональным областям:

### 1. `TestCallMentorpieceApi`
Тесты для функции `call_mentorpiece_api()`, которая отвечает за взаимодействие с AI API.

#### Тесты:
- **`test_api_key_not_found`**: Проверяет обработку отсутствия API ключа в переменных окружения
- **`test_successful_api_call`**: Проверяет успешный вызов API и корректный возврат данных
- **`test_api_timeout_error`**: Проверяет обработку таймаута запроса
- **`test_api_connection_error`**: Проверяет обработку ошибок подключения
- **`test_api_http_error_401`**: Проверяет обработку HTTP ошибки 401 (неверный API ключ)

### 2. `TestUploadRoute`
Тесты для маршрута `/upload` (генерация тест-кейсов).

#### Тесты:
- **`test_upload_success`**: Позитивный тест успешной генерации тест-кейсов
- **`test_upload_missing_description`**: Проверяет валидацию отсутствия описания формы
- **`test_upload_empty_description`**: Проверяет валидацию пустого описания формы
- **`test_upload_api_error`**: Проверяет обработку ошибок от AI API
- **`test_upload_empty_response`**: Проверяет обработку пустого ответа от API

### 3. `TestEvaluateRoute`
Тесты для маршрута `/evaluate` (оценка качества тест-кейсов).

#### Тесты:
- **`test_evaluate_success`**: Позитивный тест успешной оценки тест-кейсов
- **`test_evaluate_missing_test_cases`**: Проверяет валидацию отсутствия тест-кейсов
- **`test_evaluate_empty_test_cases`**: Проверяет валидацию пустых тест-кейсов
- **`test_evaluate_fallback_model`**: Проверяет механизм fallback на вторую модель при ошибке первой
- **`test_evaluate_api_error_no_fallback`**: Проверяет обработку ошибок без возможности fallback

## Используемые технологии и подходы

### Mocking
- **unittest.mock.patch**: Используется для замены реальных функций и методов на mock-объекты
- **pytest-mock**: Интеграция pytest с mocking возможностями
- **monkeypatch**: Встроенная фикстура pytest для изменения атрибутов модулей
- **Цель mocking**: Избежать реальных HTTP запросов к AI API, сэкономить токены и ускорить тесты

### Модели AI в тестах
- **Worker модель** (`gpt-5.1-2025-11-13`): Используется для генерации тест-кейсов, возвращает фиктивные тест-кейсы
- **Judge модель** (`claude-sonnet-4-5-20250929`): Используется для оценки качества, возвращает фиктивную оценку
- **Fallback модель** (`google/gemma-3-27b-it`): Используется при ошибке основной Judge модели

### Сценарии тестирования

#### Positive Tests
- Успешное выполнение основных функций приложения
- Корректная обработка валидных входных данных
- Правильное формирование ответов API

#### Environment Tests
- Проверка загрузки конфигурации из переменных окружения (`MENTORPIECE_API_KEY`)
- Валидация наличия необходимых зависимостей

#### Error Handling Tests
- Обработка сетевых ошибок (таймаут, отсутствие подключения)
- Обработка HTTP ошибок (401 Unauthorized, 429 Rate Limit)
- Обработка ошибок парсинга JSON
- Graceful degradation с fallback механизмами

## Запуск тестов

### Требования
- Python 3.8+
- pytest
- pytest-mock (опционально, для дополнительных возможностей mocking)

### Установка зависимостей
```bash
pip install pytest pytest-mock
```

### Запуск всех тестов
```bash
pytest tests/unit/test_app.py
```

### Запуск конкретного тестового класса
```bash
pytest tests/unit/test_app.py::TestCallMentorpieceApi
```

### Запуск конкретного теста
```bash
pytest tests/unit/test_app.py::TestUploadRoute::test_upload_success
```

### С подробным выводом
```bash
pytest tests/unit/test_app.py -v
```

## Покрытие кода

Тесты покрывают следующие аспекты приложения:

1. **Функция call_mentorpiece_api**:
   - Загрузка API ключа
   - Формирование HTTP запросов
   - Обработка различных типов ошибок
   - Парсинг ответов API

2. **Маршрут /upload**:
   - Валидация входных данных
   - Интеграция с AI API для генерации тест-кейсов
   - Формирование ответов клиенту

3. **Маршрут /evaluate**:
   - Валидация входных данных
   - Интеграция с AI API для оценки
   - Механизм fallback на альтернативную модель
   - Формирование ответов клиенту

## Лучшие практики тестирования

### Mocking стратегии
- Mock на уровне HTTP запросов (`api_session.post`) для изоляции внешних зависимостей
- Mock переменных окружения для тестирования конфигурации
- Использование side_effect для имитации исключений

### Структура тестов
- Каждый тест проверяет одну конкретную функциональность
- Четкие имена тестов, описывающие проверяемое поведение
- Использование setup_method для инициализации тестового клиента Flask

### Отчетность
- Подробные комментарии в коде для объяснения логики тестов
- Проверка не только успешных сценариев, но и ошибочных
- Валидация как положительных, так и отрицательных исходов

## Расширение тестов

Для расширения покрытия можно добавить:

1. **Интеграционные тесты**: Тестирование взаимодействия между маршрутами
2. **Тесты производительности**: Проверка времени отклика API
3. **Тесты безопасности**: Валидация входных данных на предмет инъекций
4. **Тесты UI**: Если добавить фронтенд компоненты
